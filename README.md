# Лабораторная работа №4 по python

Реализованы: алгоритм для составления чисел фибоначи, insert sort, heap sort, radix sort, а также бенчмарк для сравнения, стек


## 1 Запуск и использование CLI

```bash
# Интерактивное меню
uv run algo

# Отдельные подкоманды CLI
uv run algo fib 10
uv run algo sort --algo all --dataset random --size 20
uv run algo stack A B C
uv run algo gen --type nearly_sorted --size 15
uv run algo bench --repeats 5 --sizes 100 1000 10000
uv run algo test all
```

## 2. Анализ сложности алгоритмов и структур данных

| Компонент / Алгоритм | Временная сложность (лучший) | Временная сложность (средний) | Временная сложность (худший) | Дополнительная память | Примечание |
| :--- | :---: | :---: | :---: | :---: | :--- |
| **`fibonacci_iterative`** | $O(n)$ | $O(n)$ | $O(n)$ | $O(1)$ | Хранятся только два предыдущих числа `a` и `b` |
| **`fibonacci_recursive`** | $O(n)$ | $O(n)$ | $O(n)$ | $O(n)$ | Глубина стека вызовов пропорциональна $n$ (с аккумулятором) |
| **`insertion_sort`** | $O(n)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ ($O(n)$ копия) | На отсортированном входе внутренний цикл не делает сдвигов |
| **`heap_sort`** | $O(n \log n)$ | $O(n \log n)$ | $O(n \log n)$ | $O(1)$ ($O(n)$ копия) | Построение кучи за $O(n)$, $n$ просеиваний по $\log n$ |
| **`radix_sort` (LSD)** | $O(d \cdot (n + k))$ | $O(d \cdot (n + k))$ | $O(d \cdot (n + k))$ | $O(n + k)$ | $k = 2^{\text{bits}} = 256$, $d$ — количество байт в диапазоне чисел |
| **`Stack.push`** | $O(1)$ | $O(1)$ | $O(1)$ аморт. | $O(1)$ | Добавление в конец списка Python (`list.append`) |
| **`Stack.pop`** | $O(1)$ | $O(1)$ | $O(1)$ | $O(1)$ | Извлечение с конца списка (`list.pop`) |
| **`Stack.peek`** | $O(1)$ | $O(1)$ | $O(1)$ | $O(1)$ | Чтение по индексу `[-1]` |
| **`Stack` (вся структура)** | — | — | — | $O(n)$ | Хранение $n$ элементов в списке |

### Анализ:
1. **`insertion_sort`**:
   - На отсортированном наборе (`sorted`) работает за линейное время $O(n)$, так как внутренний цикл `while` завершается на первом же сравнении. Алгоритм успешно справляется с $1\,000\,000$ (0.14 с) и даже $10\,000\,000$ элементами (1.11 с), опережая все остальные сортировки. На $100\,000\,000$ время превышает лимит отсечки 3 с.
   - На неотсортированных данных проявляется сложность $O(n^2)$: при размере $\ge 1\,000\,000$ время исчисляется часами, поэтому зафиксирована отсечка `N/A (>3s, O(n²))`.
2. **`heap_sort`**:
   - Демонстрирует сложность $O(n \log n)$ на всех типах входных данных.
   - На чистом Python при $n \ge 1\,000\,000$ время выполнения превышает порог 3 секунды (~8 с на 1M, ~100 с на 10M), поэтому срабатывает отсечка `N/A (>3s)`.
3. **`radix_sort`**:
   - Поразрядная LSD-сортировка ($O(d \cdot (n + k))$) демонстрирует колоссальное преимущество на больших массивах целых чисел: на $1\,000\,000$ элементов сортирует данные быстрее секунды (0.15–0.92 с), опережая пирамидальную сортировку почти в 10 раз. На масштабах $\ge 10\,000\,000$ время превышает порог отсечки 3 с (~10.2 с на 10M).
